# 发布与精确覆盖

本包不含线上操作实现。调用实际飞书 CLI/API 的执行者必须使用已登录的最小必要权限；凭证和附件映射留在私有运行目录。

1. 明确本次用户授权的行/稳定 record ID、输出字段、保留源字段、覆盖范围。不能仅依靠视图行序号写入。
2. 下载该记录的原 `2D图纸` 附件，绑定原件哈希和完整型号。和 `替换图纸` 历史附件分开保存。
3. 本地构建、自动门禁、原图独立目检、当前输出哈希证据全部完成；失败的单张不进入发布队列。
4. 先将新 PDF 上传，取得真实新 token；更新目标字段时暂时同时保留旧附件。
5. 从实际更新后的记录回读附件列表，下载新 token，核验字节 SHA256 与已验收输出一致。
6. 只有在当前用户已明确授权覆盖时，精确移除该记录目标输出字段里的旧 token。新验收版保留；其他字段和原 `2D图纸` 不改。
7. 回读核对字段最终只含应保留附件。保存私有事务记录：旧列表、新 token、每一步结果、下载哈希。

失败停止：新上传/更新/下载验证任一步失败，保留旧附件，不尝试先清空字段再上传；异常重试前先查询当前记录，避免重复附件。批次单一发布者，避免并发丢失字段更新。

公开仓库禁止包含 token、租户/记录映射、下载链接、供应商图纸、生成成品、QA 图片、个人路径或运行日志。公开发布源码前审查 git 暂存内容及历史；不要将旧私库改为公开来代替干净新库。
