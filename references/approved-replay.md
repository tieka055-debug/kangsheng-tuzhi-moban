# 已认可配方：冻结与确定性重放

## 适用范围

此入口解决“同一个供应链原件，再做一次已经认可的样子”：把已认可操作冻结成配方，由程序执行，不再让模型重新分析、裁切和排版。

- **同一原件**指 PDF 文件 SHA256 精确一致，而不是文件名相同、型号相近或肉眼看起来相同。
- **认可视觉**指用户明确认可的基线成品。冻结时需要保留认可依据，并核对计划重放后的整页渲染与基线一致。
- **工程发布**仍使用 Manifest v2 的源清单审核、`build`、独立最终审核与 `verify --review`。视觉重放不会生成工程发布凭证。

新型号、未知 SHA256 或缺少对应认可配方的原件，先走 [Manifest v2](manifest.md) 的整页 `SOURCE_INVENTORY_GATE`、源审与建配方。不要把已知原件的裁切坐标套到新原件；字号、表格内容和公差格也不得按相似型号补齐。exact replay 只核对已冻结视觉，不充当新源完整性、颜色语义或 layout family 学习的证明。

## 命令

以下名称均为占位符；真实输入、输出和注册表放在仓库外的私有工作目录。

### 1. 冻结已认可计划

```sh
python scripts/kangsheng.py freeze-approved PLAN.json \
  --baseline APPROVED.pdf \
  --output RECIPE.json \
  --approval-note '用户明确认可'
```

`PLAN.json` 必须真实对应这份原件和已认可成品；`--approval-note` 记录实际认可依据，不是让程序替用户批准。冻结过程按计划生成候选，比较整张认可基线渲染；不一致就查计划、原件或环境，不覆盖基线让检查通过。

原件、认可基线和资产保持只读；冻结配方绑定它们的本机路径及哈希，不复制这些私有文件。因此后续重放须保留对应材料。已存在的冻结配方不会被覆盖，更改方案时使用新的配方文件名。

### 2. 重放单份原件

```sh
python scripts/kangsheng.py replay RECIPE.json --output WORK/replay
```

使用配方中已绑定的原件和资产，不重新推断位置。核验源、配方、资产、引擎及依赖后执行已冻结操作，再核对整页渲染基线。输入或环境验证失败时检查报错与核验证据，修复原因或为真正变化的方案重新审核、冻结；不要静默降级为“相似结果”。

### 3. 重放已登记原件批次

```sh
python scripts/kangsheng.py replay-batch --registry REGISTRY.json \
  --sources SOURCE_A.pdf SOURCE_B.pdf \
  --output-root WORK/replay-batch
```

注册表将原件 SHA256 映射到其冻结配方。按实际文件哈希匹配，不按文件名、顺序或型号模糊匹配。未登记的源交回源审与建配方流程，不套用另一项坐标。此批次不是 v2 `batch`，不会跳过或替代其先导项及发布门禁。

注册表使用以下占位符结构，`recipe_path` 相对注册表所在目录解析：

```json
{
  "schema_version": 1,
  "recipes": [
    {"source_sha256": "SOURCE_SHA256", "recipe_path": "RECIPE.json"}
  ]
}
```

批次未登记的 SHA256 标记为 `skip_needs_inspection`，同一批重复源标记为 `skip_duplicate_source`，核验失败标记为 `REPLAY_FAILED`；其他项继续处理。每份已知原件使用输出根目录下的 SHA256 子目录。

## 配方契约

冻结配方的 `recipe_schema` 为 `kangsheng-approved-recipe-v1`。

| 部分 | 含义 |
|---|---|
| `configuration` | 沿用常规 cfg 的 `source`、`fields`、`groups`、`assets` 等配置；要求显式 `color_profile`，可为 `cyan-gold-v1` 或 `legacy-v1`，缺省或未知值均停止。可按具体已认可原件绑定 `stroke_profile`；缺省保持原源线宽 |
| `operations` | 已认可的有序操作序列，只执行明确列出的操作 |
| 源绑定 | 原件内容 SHA256 及配方中的本地定位信息 |
| 配方绑定 | 配方内容哈希，防止操作或配置被悄悄改动 |
| 资产绑定 | 实际品牌、字体等外部资产哈希 |
| 环境绑定 | `kangsheng.py`、`frame.py`、`approved_recipe.py` 文件哈希及 PyMuPDF/fitz 版本，防止引擎变化改变结果 |
| 基线绑定 | 已认可成品整页渲染哈希，核对完整输出而非只看局部 |

操作类型：

- `source`：从原 PDF 直接复制指定原矢量区域；技术值、表格、尺寸图、公差及符号由原件承载，不用 OCR 重打。
- `native_paths`：只在逐源认可配方中使用。按已核定源框从该原件读取矢量路径，强制匹配路径数量与联合边界，在目标格内等比绘制；可用于已认可的非可提取文字/技术符号重排，不从其他型号借用路径或数值。未知绘图算子、源结构变化或非等比放置均停止。
- `rect` / `line`：执行配方明确指定的页框、表格闭合线或版式线条，不凭空添加技术内容。
- `text`：目前只接受真实日期元数据，格式为 `YYYY-MM-DD` 或 `DD-MM-YYYY`，分隔符也可为 `.` 或 `/`；不用于重录尺寸、性能、公差或其他技术数值。

“精确复现”的核验依据是绑定环境下以 **4×、RGB、无透明通道渲染的整页哈希**，冻结要求零差异像素，不是宣称 PDF 文件字节必然完全相同，也不是自动证明工程语义正确。

## 认可版式约定

- **历史冻结配方的兼容行为**：颜色策略按配方显式保存。`cyan-gold-v1` 对绑定旧稿的青色针脚转金，其余非白内容转蓝；`legacy-v1` 保留旧行为。冻结时必须明确选择并绑定策略，新策略不全局覆盖旧稿。该旧两色枚举不是新源 canonical 规则；新源须按供应商/family 的技术强调角色映射低饱和金，普通工程内容蓝，未知色义局部审阅。
- 细线兼容策略 `legacy-thin-stroke-boost-v1` 只可经具体原件、认可 PDF 与 4×零差冻结后使用；默认 `source` 保留源线宽，不能把旧兼容加粗推广到其他图纸。
- **历史冻结配方的兼容行为**：原配方如搬运原矢量公差单元格，精确重放时仍保留全部有内容格子及闭合网格，不能悄悄改动已认可基线。**新源 canonical 成品**使用获认可的英文疏排栏；源公差所有字段在 `AUTHORIZED_TRANSFORM` 账本逐项与输出核对，不能因视觉替换而从技术清单排除，也不能跨型号手工猜值。
- 空公差格的删除依据必须来自这份原件，不能由另一型号的空列推断；新源清单的排除区仍按 v2 审核。
- 投影符号保持完整，并在其专用格内居中；型号表位于右上，性能块位于其下。
- 原版品牌资产和明确认可的布局都是冻结内容；改色、换字体、换资产或改坐标不是原配方的无条件续用。

## 输出与复用

| 产物 | 用途 |
|---|---|
| `drawing.pdf` | 重放的候选或已核验成品；是否成功以同目录报告为准 |
| `preview.png` | 4× 整页预览 |
| `replay-check.json` | 源、配方、输出和视觉哈希及当前核验状态 |

冻结在配方旁新建 `RECIPE-freeze-随机后缀` 诊断目录，另保留 `baseline-preview.png`；冻结失败时不生成配方。重放沿用同一输出目录前会确认目录归属，只有配方、原件、PDF、预览及整页视觉哈希均符合已有成功记录才复用，不把“文件已存在”当作通过。输入绑定完好但成品被改动时，会重新渲染并核对整页基线。不同配方、非受管已有产物及符号链接/硬链接产物不会被覆写；重放目录不得与包含 `release.json` 的工程发布目录混用。

## 状态与工程边界

重放成功的状态为：

```text
APPROVED_VISUAL_REPLAY_VERIFIED
engineering_release=false
```

此状态仅说明已冻结认可视觉的确定性复现。`freeze-approved`、`replay`、`replay-batch` **不产出 `release.json`**，不得把它们的结果改标为 `RELEASE_READY`，也不应替用户补写源审或终审 PASS。

工程发布继续遵循：完整原件源审 → v2 `build` 自动 QA → 不同审核者/独立运行的终审 → `verify --review` → `release.json`。现有 [发布顺序](publishing.md) 不变。

## 跨窗口最短接力

开始前优先寻找：

1. 项目私有 `handoff/认可版快速接力.md`；
2. 本机 `~/.local/share/kangsheng-tuzhi/registry.json`；
3. 注册表指向的原件、冻结配方、认可基线和最近一次验证结果。

核对 SHA256 后直接重放，不重新翻聊天、截图找坐标或另写一次性生产入口。缺失或不匹配的材料需要补齐或重新源审，不猜测沿用。

以上接力材料及注册表都属于本机私有状态。公开仓库只保存通用代码、品牌资产、文档和合成测试；不上传源稿、成品、真实业务记录 ID、绝对私有路径或真实配方数据。文档示例始终使用占位符。

## 效率口径

- 同一原件的成本是读取、确定性渲染和哈希核验，不需要再次模型排版。
- 新版式需要完整原件审阅、裁切确认、布局确认及工程审核；不能用已知配方重放时间估计未知版式的交付时间。
- 分别记录或说明渲染、自动核验、人工/代理审阅的耗时。一次完整审计的总耗时不等于渲染速度。
